Готов ли отчёт через API Яндекс Маркета. Контроль полноты селлера

Как проверять покрытие периода, когда несколько запросов выгрузки завершаются в разное время.

Редакция Pomonete · 21 ноября 2026 · Условные данные

Селлер собирает аналитику Яндекс Маркета через API. Часть месячных файлов приходит сразу, остальные ещё формируются. Выгрузка с пропуском легко выглядит как падение продаж. Введите отдельный контроль полноты, прежде чем передавать цифры владельцу магазина.

Что значит готовый интервал

Храните ключ запроса, выбранные даты, область магазина и факт успешного разбора. Статус создания отчёта отличается от получения файла. Для пустой корректной выгрузки зафиксируйте признак, что она прошла проверку. Тогда пропуск не маскируется нулём.

Чтобы пересобрать расчёт «Доля полностью загруженных интервалов» для своего магазина, перенесите в него исходные числа. В формуле A обозначает «интервалы с готовыми файлами», B обозначает «интервалы по плану». Деление отвечает за долю, умножение на 100 переводит её в проценты. При нулевом знаменателе долю оставляют пустой. Запишите рядом период и охват каждого среза. Если для одной строки известна только оценка, оставьте пояснение непосредственно рядом с ней: по итоговой цифре источник уже не восстановить.

Доля полностью загруженных интервалов = A ÷ B × 100

В сценарии «Утренняя проверка» в формулу подставляем интервалы с готовыми файлами = 22, интервалы по плану = 30. Получается 73,33%. Остальные заказы на генерацию ещё в очереди или в работе.

В сценарии «После повторной проверки» в формулу подставляем интервалы с готовыми файлами = 28, интервалы по плану = 30. Получается 93,33%. Обработаны дополнительные файлы, у двух интервалов нет пригодного результата.

В сценарии «Контрольная выгрузка» в формулу подставляем интервалы с готовыми файлами = 30, интервалы по плану = 30. Получается 100%. У каждого интервала сохранился файл и дата проверки. Учитываются даже корректные пустые интервалы.

Если «Утренняя проверка» взять за исходную точку, «После повторной проверки» меняет показатель «доля полностью загруженных интервалов» на 20 п. п., а «Контрольная выгрузка» на 26,67 п. п.. Между двумя последними строками разница составляет 6,67 п. п. при вычитании второй из третьей. Смотрите, какой именно вход изменился между строками. Если менялись объём и условия одновременно, итог сравнения относится ко всему сочетанию.

От меньшего результата до большего в таблице 26,67 п. п.. При переходе из «После повторной проверки» со значением 93,33% в «Контрольная выгрузка» со значением 100% условия заданы явно. Этот интервал описывает три построенных случая, а для вероятности исходов нужна история. В рабочей записке полезно назвать минимальное значение, при котором сохранится ваше решение. Если такой порог попадает внутрь интервала, подтвердите спорный параметр до того, как менять процесс.

Где теряются ошибки

Дата в настройках может отличаться от даты бизнес-отчёта из-за выбора события и часового пояса. Возьмите два соседних дня и найдите запись, которая должна пройти ровно один раз. Отдельно контролируйте ошибки формата и доступа по магазинам.

У сценария «После повторной проверки» есть входы: интервалы с готовыми файлами, интервалы по плану. Для каждого впишите, где взять факт и с каким временным лагом он поступит. Опорой будут исходная выгрузка, журнал загрузок и контрольные суммы. Если один источник обновляется быстрее другого, зафиксируйте общий момент доступности. При существенном разрыве покажите последние данные отдельным оперативным значением.

Перед обновлением отчёта сохраните источник, параметры запроса, время выгрузки и число строк на каждом шаге. Сначала проверяют ключ и единицу наблюдения, потом сравнивают итоговые суммы. Одно и то же значение в двух строках может быть законным: совпадение суммы само по себе слабо доказывает дубль. Подключив справочник, проверьте, какие записи не сопоставились, и разнесите их по причинам до пересчёта показателя.

Что сильнее всего меняет результат

От результата 93,33% в строке «После повторной проверки» пересчитайте несколько вариантов. Проверьте «интервалы с готовыми файлами», «интервалы по плану». Прибавка около десятой доли на вход показывает реакцию за один шаг. Целые числа сохраняем целыми. Для долей, где прирост выводит числитель за предел базы, пробуем уменьшение. Все остальные параметры при каждой подстановке сохраняются.

  • «Интервалы с готовыми файлами» меняется с 28 на 25. При прежних остальных входах получается 83,33%, сдвиг составляет -10 п. п..
  • «Интервалы по плану» меняется с 30 на 33. При прежних остальных входах получается 84,85%, сдвиг составляет -8,48 п. п..

Больше всего изменила итог подстановка «интервалы с готовыми файлами». Отклонение составило -10 п. п.. До сбора новых данных оцените, насколько правдоподобен такой шаг. Например, расход может подтверждаться документом, а объём пока наблюдается лишь частично. Уточняйте прежде всего те входы, где одновременно возможен заметный сдвиг и мало подтверждений.

Проверьте также архив исходников по размеру и читаемому заголовку. Нулевой размер или другая структура могут выглядеть как файл, но не доказывают полноту. Загрузчик сохраняет время запроса и контроль результата для каждой части.

Как показывать статус команды

Выводите с итогом количество готовых интервалов и список недостающих. Для неполного файла разрешайте предварительный просмотр с видимой пометкой. При загрузке подтверждённой недостающей части обновите только её раздел и повторите проверку месяца.

При повторном импорте берите ту же исходную выборку и фиксируйте, какие записи действительно изменились. В стабильном отчёте сумма после второго прогона того же набора остаётся равной первой. Отложенные корректировки могут изменить поздний снимок, поэтому журнал версий пригодится для ответа на вопрос, когда возникло отличие. Дайте пользователю отчёта ссылку на строку, которую можно проверить вручную.

Для управленческой встречи подготовьте два небольших примера из рабочих записей. Первый сверяет «доля полностью загруженных интервалов» при базовых условиях «Утренняя проверка». Второй берёт изменившуюся строку и объясняет, какой источник исправлен. Селлеру Яндекс Маркета будет проще повторить расчёт на новой группе, если видны исходные значения, дата анализа и момент, когда итог станет достаточно точным для решения.
